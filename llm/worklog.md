# roam worklog

Dated decisions and notable findings. The current design lives in `plan.md`; this file records how it got there.

## 2026-10-20

- **No clock in the library.** `BuildContext` keeps logs only. Reading time in wasm means a call out to JS, so callers time stages themselves.
- **Detail mesh ties stay recast-aligned.** Detail heights are multiples of `cell_height`, so the "error greater than max error" checks often compare equal values, and `triangulate_hull` often compares equal ear perimeters. roam resolves these in `float` like recast, navcat in JS doubles. The detail parity test allows a small budget of tied meshes.
- **Flat tile-wide poly arrays.** `NavMeshPoly` keeps `vertex_base`/`vertex_count` into tile-wide `poly_vertices`/`poly_neis`, instead of navcat's per-poly arrays or recast's fixed `verts[6]`. Node links are a chain through the world link pool (`first_link`, `last_link`, `next`) that appends at the tail, keeping navcat's link order.
- **Ref 0 is a valid ref; navcat sometimes treats it as "none".** Poly node 0 with sequence 0 serializes to `0`, which is falsy in JS. Affected places in navcat:
  - `findNearestPoly` failure leaves `nodeRef = 0`.
  - `findRandomPoint` and `findRandomPointAroundCircle` treat a selected ref of 0 as no selection. On nav-test this makes navcat fail a random-point call, which also skips two random draws, so every later call reads a shifted random sequence.
  - `findLocalNeighbourhood` and `getPolyWallSegments` skip links and portal intervals whose ref is 0.
  - `raycast` and any-angle search pass `0` as "no previous ref".
  roam uses `INVALID_NODE_REF` everywhere. The navcat fix is `llm/navcat-ref-zero-truthiness.patch`, covering `nav-mesh-api.ts`, `nav-mesh-search.ts` and `local-neighbourhood.ts`.
- **BV tree bounds are quantized recast-style, with snapping.**
  - Problem: navcat stored leaf bounds as unrounded `(v - tile_min) * quant_factor`. Grid-aligned polys produce near-integers, and the query snaps its box to integers (`& 0xfffe`, `| 1`), so membership near tile-grid boundaries depended on float noise. On nav-test, roam (float) and navcat (double) disagreed on 26 of 200 polygon queries and 3 of 200 nearest-poly results. An internal node also had equal x/z extents, so float and double split on different axes.
  - Recast (checked `createBVTree`): truncates min and max to `unsigned short`, in float. Correct, since the query's even/odd snapping covers the truncation, but it has the same float-versus-double split at integers.
  - Decision: recast's integer layout (`uint16_t bmin[3]`, `bmax[3]`, truncation, clamp to `0..0xffff`), plus snapping. Any quantized value within `1e-3` of an integer is snapped to it before truncating. Bounds are integers, the longest-axis choice is exact, and grid-aligned values agree in float and double.
  - navcat needs the same change for parity: `llm/navcat-bv-tree-quantization.patch` (applies to `src/query/bv-tree.ts`). With it applied to a scratch copy of navcat, all 16 parity tests pass exactly: BV tree, 200 nearest-poly queries, 200 polygon queries and off-mesh connection links. Until navcat has the patch, `nav_mesh_matches_navcat_on_nav_test` fails.
- **Floating point contraction is off** (`-ffp-contract=off` on roam's targets). clang on arm64 fuses `a * b - c * d` into FMA by default, so `tri_area_2d(a, b, b)` came out as a tiny nonzero instead of exactly 0. That flipped funnel decisions at the end of straight paths: 44 of 180 straight, crossing and smooth paths attached a different ref to their end point than navcat. Contraction also differs between compilers and platforms, so turning it off is a determinism fix on its own. MSVC's default `/fp:precise` doesn't contract.
- **Query parity on nav-test** (60 path pairs, with both navcat patches applied in a scratch copy):
  - Exact: `find_path` results and node paths, raycast, `move_along_surface`, local neighbourhood, wall segments, random points.
  - Straight path 2/60, crossings 2/60, any-angle and sliced 2/60: precision ties at exact mesh vertices and edges. Examples: a crossing point that lands exactly on the end vertex in only one precision, and an any-angle raycast that ends exactly on a portal edge midpoint.
  - Smooth path 14/60: the same vertex ties, compounded over many 0.5-unit steps, plus the navcat zero-step bug (see 2026-10-21).
  - Test inputs only use points that are directly over a poly. Nearest-poly positions projected onto poly boundaries put rays and moves exactly on edges, which gave spurious tie mismatches.

## 2026-10-21

- **navcat bug, fixed in both: `findSmoothPath` with a zero-length step.** If the steer target equals the current position (for example, standing exactly on an off-mesh connection start), `Math.min(stepSize, 0) / 0` is NaN. `moveAlongSurface` rejects the NaN target and the smooth path stops after its first point. roam steps zero distance when the length is 0, so the off-mesh connection is taken; `find_smooth_path_takes_off_mesh_connection_from_its_start` covers it. The navcat fix is `llm/navcat-smooth-path-zero-step.patch`.
- **Query path ties are accepted.** The queries parity test allows `pair_count / 20` tied pairs (3 of 60) for straight paths, crossings, any-angle and sliced node paths, which each tie on 2 of 60. Smooth paths are compared on success and their end point only, since one early tie shifts every later step; with the zero-step patch all 60 end points match. Everything else stays exact.
- **Blocks: generators, chunky tri mesh, merge positions, flood fill.** On nav-test (32-voxel tiles, border 4 for tiled), solo and tiled tiles match navcat exactly in tile positions, bounds, vertices, polys, neighbours, flags, areas and the full node graph, including cross-tile portal links. Chunky tri mesh nodes, triangles, 40 rect queries and 40 segment queries match, and so does flood fill. Detail meshes show the known ties: 2 of 134 solo polys and 5 of 154 tiled polys, since tile borders add more grid-aligned samples. Generator tile tests allow 1 in 25 tied detail meshes, and a tie is any mismatch within one vertex.
- **navcat bug, fixed in both: `mergePositionsAndIndices` re-adds the first vertex.** `if (!idx)` treats index 0 as missing, so every later use of the first merged position appends a duplicate vertex. roam checks for presence; the navcat fix is `llm/navcat-merge-positions-index-zero.patch`. roam also merges `-0` with `0`, like navcat's string keys.
- **roam's chunky tri mesh accepts an empty mesh**, returning no nodes. navcat reads `items[0]` and throws.
- **Intermediates stay with the generators.** Like navcat, `generate_solo_nav_mesh` and `generate_tiled_nav_mesh` return every stage's output (tiled keeps one per non-empty tile, and frees empty tiles). Callers release them with `release(intermediates)` and keep the nav mesh. Follow-up: an option to skip keeping them, for large tiled builds.
- **Agents: path corridor, local boundary, obstacle avoidance, crowd.** Parity on nav-test's tiled mesh: local boundaries at 24 random points and obstacle avoidance (20 adaptive and grid setups) match navcat exactly. A flat scene (floor plus three boxes, 16 agents crossing through each other for 240 frames with every update flag on) matches every frame within 4e-6 and every state. On nav-test, 12 agents match exactly in xz up to frame 34. Divergence starts from tied detail meshes: agents on tile (2,0) poly 5 get different heights, and the crowd's 3D distances (neighbour queries, local boundary refresh) carry that into xz. All final states still match.
- **Crowd agent ids are reused.** Agents live in slots indexed by an `IndexPool`, like tiles, so removed agents free their slot. navcat's string ids only grow. Iteration stays in ascending id order, as in navcat.
- **Agent params use default member initializers** for navcat's optional fields: `path_optimization_range` (0 means `radius * 30`), `query_filter`, `obstacle_avoidance`, `auto_traverse_off_mesh_connections` and `debug_obstacle_avoidance`. Designated initializers can leave them out.
- **Local boundaries are fixed size** (8 segments, 16 polys) inside the struct, and the crowd's neighbour grid reuses scratch arrays on the `Crowd`, so steady-state updates don't allocate for them.
- **Debug helpers** (`roam/debug/debug.h`, part of core like navcat's `src/debug.ts`) return `DebugPrimitives`, an `Array<DebugPrimitive>` of flat float positions and colours, plus indices for triangles and scales for boxes, with navcat's opacity, line width and point size hints. Empty primitives are dropped, as in navcat. A smoke test runs every helper over a generated mesh and checks each primitive is well formed.
- **Demo app** (`demos/`, opt in with `ROAM_BUILD_DEMOS`, presets `demos` and `web`). sokol, Dear ImGui and cgltf come from `FetchContent`, pinned to sokol `1847290` (2026-08-30), imgui `v1.92.9` and cgltf `v1.15`; nothing third party is committed. GL 4.1 natively (`SOKOL_GLCORE`, including macOS), WebGL2 on the web (`SOKOL_GLES3`), with hand-written GLSL for both, so there's no shader compiler step. Debug primitives are expanded on the CPU (points become octahedra, boxes become triangles), so static drawings don't depend on the camera. Per-frame geometry goes through sokol's transient buffers. Models load with cgltf, keeping material base colours for rendering and merging positions with `merge_positions_and_indices` for generation, as navcat's `getPositionsAndIndices` does. Examples so far: solo nav mesh, tiled nav mesh, find path, crowd simulation. `roam_demos "<example name>" --screenshot out.ppm` renders 30 frames, saves the framebuffer and quits, for checking demos without a screen. The web build runs in Chrome (solo generation in 10.9 ms under wasm, against 3.9 ms native).
- **Demo assets** are copied from navcat's `examples/public/models` as examples need them, with their credit files. Only `nav-test.glb` so far.
- **Search workspace.** One-shot searches allocated a fresh node pool and open list on every call, as in navcat. Recast instead allocates pools once per `dtNavMeshQuery` (`init(nav, maxNodes)`), with a 64-node "tiny" pool for `moveAlongSurface` and `findLocalNeighbourhood`. Its `dtNodePool` is a chained hash whose `clear()` just resets the bucket heads, and the crowd shares one query for all agents. roam now does the same, minus the hard caps:
  - `SearchNodePool` is a node array plus a power-of-two bucket table, at most 2 nodes per bucket. It grows instead of failing, and `clear` keeps the memory.
  - `SearchWorkspace` holds a main pool and open list, a local pool and queue, and scratch vertex and neighbour arrays. `find_node_path`, `find_path`, `find_smooth_path`, `move_along_surface`, `raycast`, `raycast_with_costs`, `find_random_point_around_circle` and `find_local_neighbourhood` take an optional `SearchWorkspace *` and use a temporary without one.
  - `find_node_path`'s search nodes now live in the workspace, not the result.
  - Sliced queries keep their own pools, now cleared cheaply, plus a raycast scratch array.
  - The crowd owns one workspace for every agent's per-frame calls.
  - The A* shortcut raycasts no longer collect a path they don't use.
  - Parity results are unchanged.
- **Demos: area filters, area costs, find shortest paths, find diverse paths, off mesh connections, flood fill pruning.** Area filters and area costs build a single-tile nav mesh by hand from the generate steps with `mark_box_area`, as navcat's examples do. Custom query filters carry their state through `QueryFilter::user_data` (cost multipliers, blocked nodes and edges for Yen's algorithm, the penalty map for diverse paths); navcat's `nextRef === undefined` is `INVALID_NODE_REF`. The app gained `app::set_level` for generated levels (area costs' 40 m floor), a `skip_unwalkable_nodes` option on `load_level` that leaves glTF nodes with `extras.walkable == false` out of the walkable geometry (bridges.glb), and `Click::ray` for picking nav mesh polys. "Click to start moving, click again to place" examples follow the mouse through `app.hover`. Examples are registered in `examples.json` order, so the app now opens on crowd simulation. Textured models (bridges.glb) draw untextured, and path lines are one pixel wide rather than navcat's world-width lines.
- **Demo generation examples: chunky tri mesh, custom glTF nav mesh, custom nav mesh generation, mark compact heightfield areas, rasterize filled volume.** The app gained a ray on `Click` and `Hover`, `app::set_level` for levels built in code, a node filter on `model::load`/`app::load_level` (tower-big's `level` and `navmesh` nodes), and `camera::look_at` to start from navcat's camera position. Examples that use navcat's 75 degree camera set it and restore the fov on shutdown. Chunky tri mesh approximates navcat's top-down orthographic camera with a 10 degree fov from far away, and moves the query region by click rather than drag. Custom nav mesh generation ports mathcat 0.0.12's `createSimplex2D` and `createMulberry32Generator` into the example and replaces three-mesh-bvh with direct vertical ray tests against the terrain grid and the house boxes. Rasterize filled volume replaces the transform gizmos with click-to-place for the selected volume plus position fields. Path lines are depth tested, unlike navcat's always-on-top lines. Assets added: `dungeon.gltf` and `tower-big.glb` (no credit files in navcat).
